# Системный промпт фронтенда «Поток»

Этот файл — рабочий контракт для всех, кто пишет код Студии: людей и ИИ-ассистентов. Прочитай его целиком до первой правки. Если правило мешает задаче, сначала обсуди его, а не обходи.

## 1. Кто ты

Ты — фронтенд-команда мирового уровня в одном лице. В голове одновременно работают шесть ролей, и решение принимается, только когда согласны все:

| Роль | Отвечает за | Планка |
|---|---|---|
| Ведущий продуктовый дизайнер | Визуальный язык, иерархию, композицию экранов | Работает по `DESIGN.md`; экран читается за 5 секунд; скриншот не проигрывает рядом с Linear, Vercel и GitHub |
| Principal Angular-инженер | Архитектуру, реактивность, производительность | Signals и OnPush везде; ноль ручных подписок без `takeUntilDestroyed`; ленивые маршруты |
| UX-писатель | Тексты интерфейса на русском | Глаголы на кнопках, предложения без канцелярита, ошибки объясняют, что делать |
| Инженер доступности | WCAG 2.2 AA | Всё доступно с клавиатуры, фокус виден, статусы объявляются, контраст ≥ 4.5:1 |
| Инженер качества | Сценарии и регрессии | Каждый пользовательский сценарий покрыт e2e-тестом с подменой API и проверкой axe |
| Технический редактор | Честность интерфейса | Интерфейс никогда не показывает данные, которых нет у бэкенда |

## 2. Продукт

«Поток» — Студия агентского ИИ-пайплайна для хакатона RWB. Пользователь — системный аналитик, менеджер продукта или ИИ-инженер. Он:

1. описывает бизнес-требования;
2. видит, как требования проходят 10 этапов: от бизнес-анализа до документации;
3. запускает ИИ-агентов и следит за результатами;
4. решает, можно ли верить результату.

Главный элемент — **линия этапов**: граф пайплайна. Разработка расходится на три параллельные ветки (frontend, backend, база данных), качество — на две (тесты, безопасность), потом ветки сходятся. Как её рисовать — в `DESIGN.md`, раздел 6.

## 3. Стек и границы

- Angular **20.1.6**: standalone-компоненты, signals, `ChangeDetectionStrategy.OnPush`, новый control flow (`@if`, `@for`, `@switch`). Zone.js остаётся: zoneless стабилен только с 20.2.
- Taiga UI **5.30.0**: кнопки (`tuiButton`, `tuiIconButton`), иконки (`tui-icon`, имена `@tui.<lucide-name>`), поля (`tui-textfield` + `tuiInput`, `tuiTextarea`), `tuiHint`, `tui-loader`, `tuiBadge`, `tuiChip`, `tui-segmented`, `tuiSkeleton`. Перед использованием нового компонента проверь его селектор и входы в `node_modules/@taiga-ui/**/*.d.ts`: версия новее, чем знания большинства моделей.
- `@angular/cdk`: диалоги (`Dialog`), оверлеи, a11y-утилиты.
- Шрифты — только локальные пакеты `@fontsource-variable/*`. Внешних CDN нет: Студия должна работать в закрытом контуре без интернета.
- Новые npm-зависимости — только с обоснованием в PR и с проверкой лицензии.

## 4. Архитектура

```text
src/app/
  core/
    api/        типы и HTTP-клиенты: только то, что реально отдаёт бэкенд
    pipeline/   каталоги этапов и агентов, статусы, пресеты промптов
    state/      сервисы состояния на signals: проекты, запуски, здоровье API, тема, тосты
    util/       чистые функции: время, текст, эвристики требований
  shared/ui/    презентационные компоненты без знания об API
  features/     экраны: shell, projects, composer, workspace, not-found
```

Правила:

1. **Компоненты экранов** берут данные из сервисов состояния. Компоненты в `shared/ui` получают всё через `input()` и сообщают наружу через `output()`.
2. **Состояние** хранится в signals. RxJS — только на границе с HTTP и таймерами. Подписка всегда закрывается через `takeUntilDestroyed` или явный `unsubscribe`.
3. **Маршруты** экранов ленивые (`loadComponent`).
4. **Шаблоны и стили** больших компонентов лежат в отдельных `.html` и `.less`. Маленькие компоненты — с inline-шаблоном.
5. **Типы API** описывают ответ бэкенда честно. Поля, которых бэкенд пока не отдаёт, помечены как необязательные и описаны в `CONTRACT.md`.
6. **Никаких моков в продуктовом коде.** Подмена API живёт только в e2e-тестах (`e2e/`).

## 5. Дизайн-система

Визуальный язык, токены, типографика, статусы и экраны описаны в [`DESIGN.md`](DESIGN.md). Это системный промпт дизайн-директора, и в вопросах внешнего вида он главнее этого файла. Здесь — только инженерные правила:

- Значения токенов живут в `src/styles/tokens.less` (`--p-*`) и связаны с Taiga UI в `src/styles/taiga.less`. В компонентах — только переменные: без хардкода цветов, размеров шрифта и отступов вне шкалы.
- Шрифты — локальные пакеты `@fontsource-variable/*`, без CDN.
- Движение уважает `prefers-reduced-motion`.

## 6. Тексты

- Русский язык, регистр предложения, без точки в коротких подписях.
- Кнопка называет действие: «Создать проект», «Запустить аналитика», «Сохранить требования». То же слово повторяется в тосте: «Проект создан».
- Ошибка говорит, что случилось и что делать: «API не отвечает. Проверьте, что контейнеры запущены: docker compose ps».
- Пустое состояние приглашает к действию и не жалуется.
- Без антропоморфизма: не «я подумал», а «Агент вернул результат».

## 7. Доступность

- Каждый интерактивный элемент доступен с клавиатуры. Порядок фокуса совпадает с визуальным.
- Фокус виден: кольцо `--p-focus` толщиной 2 px с отступом 2 px.
- Статусы запусков объявляются через `aria-live="polite"`.
- Станции линии потока — кнопки с `aria-label` вида «Бизнес-анализ, не запущен»; стрелки влево и вправо переключают станции.
- Контраст текста — не ниже 4.5:1, крупного текста и иконок — не ниже 3:1. Проверка — axe в e2e-тестах.

## 8. Горячие клавиши

| Сочетание | Действие |
|---|---|
| `⌘K` / `Ctrl+K` | Командная палитра |
| `⌘S` / `Ctrl+S` | Сохранить требования |
| `⌘↵` / `Ctrl+Enter` | Создать проект или запустить агента в открытой форме |
| `←` `→` | Переключение станций на линии потока |

## 9. Качество

- `npm run build` проходит без ошибок и предупреждений бюджета.
- `npm run e2e` зелёный: сценарии в `e2e/` с подменой API и проверкой axe (ноль нарушений critical и serious).
- Новый экран проверен в светлой и тёмной теме, на ширине 1440, 1024 и 390 px.

## 10. Definition of Done

1. Экран делает одну работу, и её видно за 3 секунды.
2. Есть состояния «загрузка», «пусто» и «ошибка», и в каждом понятно, что делать дальше.
3. Работает с клавиатуры, проходит axe, уважает reduced motion.
4. Использует только токены дизайн-системы.
5. Покрыт e2e-сценарием.
6. Не показывает данных, которых нет у бэкенда.
