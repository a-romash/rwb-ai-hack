# Контракт Студии с API

Какие эндпоинты использует фронтенд, как он трактует ответы и что ему нужно от бэкенда дальше.

## Используется сейчас

| Метод и путь | Где в Студии | Как используется |
|---|---|---|
| `GET /api/health` | Индикатор «API на связи» в шапке | Опрос раз в 20 секунд, при ошибке — раз в 6 секунд; на скрытой вкладке опрос на паузе |
| `GET /api/projects` | Список проектов, командная палитра | Сортировка «Недавние» берётся из ответа, «По названию» считается на клиенте |
| `POST /api/projects` | Новый проект | Тело `{name, requirements}`; после 201 — переход в `/projects/:id/flow` |
| `GET /api/projects/{id}` | Рабочая область | Название и требования. Этапы проекта показываются участниками шагов конвейера RWB |
| `PATCH /api/projects/{id}` | Переименование, сохранение требований | Отправляется только изменённое поле |
| `POST /api/projects/{id}/jobs` | Диалог запуска агента | `{agent, prompt}`; `prompt` — инструкция этапа плюс требования. Без инструкции поле не передаётся, и бэкенд берёт требования проекта |
| `GET /api/projects/{id}/jobs/{job_id}` | Вкладка «Запуски агентов» (отладка одного агента) | Опрос: 1,5 с в первые 30 с, потом 3 с, после 3 минут — 6 с. После 20 минут в `pending` задача помечается «Нет статуса» |
| `GET /api/projects/{id}/runs` | Вкладка «Конвейер» | Берётся последний прогон по `created_at`; без прогона шаги показывают запуски агентов |
| `POST /api/projects/{id}/runs` | Кнопка «Запустить конвейер» | `{autonomy, budget: {tokens: 1500000, minutes: 60}}` |
| `GET /api/runs/{id}` | Таймлайн, панель прогона | Статусы шагов из `stages[]`, результат ворот из `stages[].gate`, бюджет, вопросы |
| `RunRead.prototype_url` | «Открыть прототип» в результате прогона | Относительная ссылка от API только для текущего опубликованного прототипа; `null` до публикации и после следующего запуска. Адрес VPS на фронтенде не задаётся |
| `GET /api/runs/{id}/events/stream` | Живое обновление | `EventSource`; на `stage.*`, `gate.result`, `question.asked`, `run.*` снимок перечитывается не чаще раза в 400 мс. Поток закрывается, когда прогон завершён |
| `GET /api/runs/{id}/artifacts`, `/files?path=` | Список артефактов | Файл открывается в новой вкладке, каталоги — без ссылки |
| `POST /api/runs/{id}/stages/{key}/retry` | «Перезапустить шаг» | Для `failed`, `stale`, `succeeded` |
| `POST /api/runs/{id}/answers` | Форма вопросов | `{answers: {Q-01: "…"}}`, по умолчанию — `default` вопроса |
| `POST /api/runs/{id}/gates/{gate}/decision` | Панель ворот, когда шаг `waiting_human` | `{decision: approve | reject}` |
| `POST /api/runs/{id}/cancel` | «Остановить» | Пока прогон идёт |

### Как читается статус задачи

| `status` | `subtype` | Студия показывает |
|---|---|---|
| `queued`, `pending`, `received` | — | В очереди |
| `started`, `retry` | — | Выполняется |
| `success` | `success` | Готово |
| `success` | `partial`, `budget` | Частично, бюджет исчерпан |
| `success` | `blocked` | Нужен ответ |
| `success` | `error`, `error_max_turns`, `unfinished`, `no_progress` | Ошибка (задача в очереди прошла, а агент — нет) |
| `failure` | — | Сбой задачи |
| `revoked` | — | Отменено |

Celery возвращает `pending` и для неизвестной задачи. Поэтому после истечения результата (`result_expires = 3600`) Студия не откатывает готовый статус и показывает сохранённый результат.

## Что нужно от бэкенда дальше

1. **Расширить `JobRead`** полями, которые харнесс уже считает (`backend/app/tasks.py`, `_PUBLIC`): `usage`, `duration_ms`, `assumptions`.
2. **Все ворота шага.** `StageRunRead.gate` отдаёт только последние ворота шага. У `verify` их два (G3 и G4), поэтому G3 в таймлайне остаётся «Не проверялись», когда G4 уже прошёл.
3. **Загрузка вложений из Студии.** API есть (`POST /api/projects/{id}/attachments?name=`, тело — файл), а формы в Студии пока нет: вложения загружает `scripts/run_pipeline.py --attach`.
